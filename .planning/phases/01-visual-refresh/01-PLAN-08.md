## Task 1: Anti-pattern sweep — hardcoded hex colors

<objective>Find and replace all remaining hardcoded hex colors in pattern components, animation files, and modified landing/dashboard/auth files</objective>

<read_first>
- components/patterns/*.tsx — all 12 pattern components
- components/animation/*.tsx — all 6 animation files
- Any files modified in Plans 01-07
</read_first>

<action>
1. Run a grep across all modified directories:
```bash
rg '#[0-9a-fA-F]{3,6}' components/patterns/ components/animation/ --type tsx -l
```

2. For each file with hits:
   - If the hex is a legitimate reference (e.g., in a URL or external API), add eslint-disable comment
   - Otherwise, replace with the appropriate semantic token:
     - Text colors → `text-foreground`, `text-muted-foreground`, `text-muted`
     - Background colors → `bg-card`, `bg-muted`, `bg-background`
     - Border colors → `border-border`, `border-[hsl(var(--border)/0.18)]`
     - Brand/primary → `hsl(var(--primary))`
     - Success/error → `hsl(var(--success))`, `hsl(var(--destructive))`
     - Chart colors → `hsl(var(--chart-N))`

3. Special cases allowed:
   - `#000` or `#000000` only in gradient stop offsets where transparent black is needed
   - Color values inside CSS `stopColor` attributes that reference `hsl(var(--...))` — verify these use the function form
</action>

- `rg '#[0-9a-fA-F]{3,6}' components/animation/ --type tsx -c` returns 0 for all files
- `npm run typecheck` passes
</acceptance_criteria>

## Task 3: Motion quality audit — prefers-reduced-motion compliance

<objective>Verify all animated components respect prefers-reduced-motion</objective>

<read_first>
- components/animation/enhanced-motion.tsx — MotionSection, MotionStagger, MotionStaggerItem, MotionPhrase, MotionOrchestrated, FloatingOrbs, AnimatedCounter
- components/animation/entrance-exit.tsx
- components/animation/interactive.tsx
- components/animation/page-transitions.tsx
</read_first>

<action>
1. For each component that renders `<motion.*>`:
   - Verify it checks `useReducedMotion()` or `usePrefersReducedMotion()`
   - If reduced motion is preferred, it should either:
     a. Render children without animation (static fallback)
     b. Return null (for decorative animations like FloatingOrbs)

2. Check for components that use CSS animations (`animate-*` Tailwind classes):
   - `animate-shimmer` — ensure `prefers-reduced-motion: reduce` media query in `styleseed-base.css` already covers CSS animations (it does at lines 59-67)
   - `animate-pulse` — covered by the same rule
   - Any custom `@keyframes` — ensure they respect the reduced motion rule

3. If any component is missing the check, add it following the pattern in enhanced-motion.tsx:
```typescript
const prefersReducedMotion = useReducedMotion()
if (prefersReducedMotion) {
  return <staticFallback />
}
```
</action>

<acceptance_criteria>
- Every file that imports `motion` from `framer-motion` also imports `useReducedMotion`
- Every component rendering `<motion.*>` has a reduced motion check
- `npm run typecheck` passes
</acceptance_criteria>
